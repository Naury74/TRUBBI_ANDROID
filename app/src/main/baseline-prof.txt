# Baseline Profile — 앱 시작 경로를 미리 AOT 컴파일해 첫 프레임까지 걸리는 시간을 줄인다.
#
# 한계를 먼저 적어 둔다: 이 파일은 기기에서 측정해 만든 것이 아니라, 시작 경로를 코드로 따라가
# 손으로 적은 것이다. androidx.benchmark 로 실제 실행을 기록해 대체하는 것이 정확하며,
# 그때는 이 파일을 통째로 덮어쓰면 된다.
#
# 앱 전체를 넣지 않는 이유: 프로필이 넓어질수록 설치 시 컴파일 시간과 용량이 늘고, "무엇이
# 시작에 필요한가" 라는 정보가 사라져 결국 프로필이 없는 것과 같아진다. 그래서 아래는
# TrubbiApp → MainActivity → TrubbiNavHost → Routes.HOME 이 실제로 지나는 것만 담는다.
#
# 규칙 형식: [플래그]L<클래스>;-><메서드>(<파라미터>)<반환>
#   H = 시작 시 실행됨(hot), S = 시작 프로필에 포함, P = 사후 시작(post-startup)
# 참고: https://developer.android.com/topic/performance/baselineprofiles/manually-create-measure
